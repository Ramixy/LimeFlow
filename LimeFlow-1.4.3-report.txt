

ДОПОЛНЕНИЕ ОТ 02.10.2026 (вторая итерация): встроенный TG WS Proxy LimeFlow
--------------------------------------------------------------------------

Диагностика (по фактам, всё проверено живыми тестами):
  1. Список воркеров Flowseal на GitHub актуален: 20 доменов.
  2. Проверка каждого воркера реальным WS-запросом (GET /apiws, TLS SNI,
     Sec-WebSocket-Protocol: binary — точно как в движке):
       - 15 из 20 стабильно отвечают 101 Switching Protocols;
       - 5 flaky/dead (offshor, cakeisalie, noskomnadzor, onedaychamp,
         nothingthere) — дают 503; движок их обходит fallback-ом.
  3. КОРЕНЬ ПРОБЛЕМЫ: встроенный в libtgwsproxy.so список содержал только
     15 доменов (5 новых отсутствовали), а его автообновление требует
     доступа к raw.githubusercontent.com КАЖДЫЙ старт после 12ч. Если GitHub
     с телефона недоступен (типично без обхода), движок навсегда остаётся на
     устаревшем списке. Несколько старых воркеров уже отдают 503 -> при
     переборе доменов соединения отваливаются по таймаутам.
  4. DNS-роутера (Xiaomi 192.168.31.1) не резолвит домены воркеров вовсе
     (только DoH). В движке DoH есть (CF/Google/Quad9/AdGuard), но с таймаутом
     1.5с; в сумме с мёртвыми доменами это давало стабильные таймауты.

Что сделано:
  1. tgwsproxy/upstream-native/src/config.rs: встроенный список CFPROXY_ENC
     обновлён до всех 20 актуальных доменов (в родной обфускации движка).
  2. НОВЫЙ ФАЙЛ tgwsproxy/src/main/java/com/amurcanov/tgwsproxy/CfDomainCache.kt:
     перед каждым стартом движка пишет в кэш проверенный список 20 доменов
     (cfproxy-domains-cache.txt), а при устаревании (>6ч) тихо докачивает
     свежий список с GitHub в фоне (таймауты 10с, ретрай-троттлинг 10мин).
     Движок читает этот кэш при старте и мерджит со встроенным.
  3. ProxyService.kt: вызов CfDomainCache.ensureFresh(cacheDir) перед
     setCfProxyCacheDir/startProxy.
  4. Rust-исходники (.so) НЕ пересобирались — Rust-тулчейна на машине нет;
     правка config.rs войдёт в силу при следующей пересборке .so, а фикс
     CfDomainCache работает уже сейчас, на текущем .so.

Проверка: gradlew :app:testDebugUnitTest :app:assembleDebug ->
  BUILD SUCCESSFUL, tests=56 failures=0. APK обновлены в releases.
Коммиты: 0ac481c (фикс доменов tgwsproxy), 75887a6 (CHANGELOG).

Что ожидать после установки:
  - Вкладка TG WS Proxy -> Старт. Первый коннект может занять 3-10с (перебор
    доменов). Дальше пул держит живые WS-соединения.
  - Если захочешь принудительно «свежий» список: останови и запусти прокси —
    кэш перезапишется проверенным списком.

    использует ТОЛЬКО его (так задумано).
